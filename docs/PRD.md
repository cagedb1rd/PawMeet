状态：2026-10-19。已实现新版导航及智能约伴、档案填写、互助填表三大 AI 场景，以及展示改进新增的 A「拍照建档」（第 7 步）与 B「社区 AI」（第 8 步），均为 mock 测试通过、小规模真实评测见 AI_EVAL，真实页面未验证。真实模型效果与历史失败见 [AI_EVAL](AI_EVAL.md)。暂不部署：以公开 GitHub 仓库展示代码，本地运行演示。

当前开放：五栏页面、模拟身份切换、档案 CRUD、社区文字 / 照片 / 点赞、活动创建 / 报名 / 取消、主人确认名片 / PNG 文件分享、两宠明确偏好冲突比较、互助发布 / 申请 / 选择 / 双方完成 / 历史与交接清单、本地持久化；附近发现支持多条件筛选与距离排序、列表 / 地图联动、参考位置与主动定位、普通 POI 搜索 / 选点 / 导航、活动 / 互助共享地点选择和文字降级。在线地图需要本地配置；真实联调限制见 [ARCHITECTURE](ARCHITECTURE.md#9-外部依据与待验证项)。智能约伴位于活动页，档案与互助智能填表留在原发布流程；其余采用规则或人工填写，真实效果与未通过项见AI_EVAL。

## 1. 定位与交付范围

面向中国年轻养狗人群的 AI 宠物社交与临时互助 Web App，默认杭州滨江。以真实养狗需求串起“认识宠物 → 找到合适宠友 → 发起约伴 / 临时互助 → 确认完成”。展示全栈交付、真实 Qwen API（文本与视觉白名单模型）、结构化输出、规则校验、多模型评测与 AI Coding 工作流。

首版聚焦狗狗；数据结构保留 species，但不扩展猫狗跨物种匹配。人工录入与规则查询先闭环，AI 融入对应表单。所有下述核心功能都在首版计划内，优先级决定顺序，不代表静默删减。

| 范围 | 首版内容 |
| --- | --- |
| 核心闭环 | 档案、主人确认社交名片、宠友筛选与比较、地图、约伴、互助状态流、智能约伴、档案与互助智能填表 |
| 轻量配套 | 动态浏览 / 发帖 / 图片 / 点赞，活动报名 / 取消 / 参与者 |
| 展示改进 | 已实现：A 拍照建档，视觉模型识别照片生成档案草稿；B 社区 AI，发帖标题 / 话题标签草稿与发布前两层文本预检。验收条件见下方 |

| 明确排除 | 原生 App、PWA / Service Worker / 离线安装、真实认证、聊天、支付、跨设备同步、真实寄养交易、复杂后台、向量库 / RAG |

## 2. 演示机制与信任边界

- 5 个可切换身份；共 25 个狗狗档案：5 个归可切换用户，20 个归仅展示的虚构主人。用户表共 25 条，只有前 5 个出现在切换器中。
- 初始 12 条帖子、6 场活动、8 条互助需求，覆盖常用状态；至少一条开放互助可让两个可切换身份完成全流程。种子版本固定，重置时基于当前中国日期生成可体验的未来时间。
- 当前种子坐标：滨江 15、萧山 4、上城 3、西湖 3；均为虚构公共区域点位，不是家庭地址或真实用户位置，具体值以 seed.ts 为准。已有浏览器坐标不自动覆盖；仅首次建立 / 用户明确重置使用当前种子分布。
- 演示边界集中在“我的 → 演示与本地数据”，全局身份入口标明模拟身份；地点来源与地图图例保留必要标记，不在所有页面重复声明。切换身份共享该浏览器同一份数据，不触发登录或网络同步。
- 刷新保留修改；另一浏览器 / 无痕窗口是独立副本；重置弹窗说明将清除当前浏览器演示修改和上传图片。业务内不收手机号、微信号或门牌地址。
- 种子内容注明虚构，静态图片需可使用且记录来源。AI 生成内容标注“AI 草稿”，主人确认后标注已确认；专业行为判断和服务保障不在产品承诺内。

### 智能约伴验收条件

- 新版导航、双列首页和附近地图 / 互助结构保持；智能约伴只在活动页，旧 /assistant 跳转活动页。
- 需求支持时间、公共地点、1/3/5/10km、类型、体型 / 互动偏好、硬排斥和软偏好；粗略日期 / 时段足以直接查询；缺少日期才询问日期，不要求精确到分钟。只有发布活动时需要具体未来起止。
- 优先检索未来未满活动，硬条件确定性检查，部分满足的软偏好展示差异；不自动报名。无匹配可选择组局；明确自己创建并确认可跳过活动查询。
- 组局按需原生多工具调用，候选宠友来自本地数据，地点来自高德或用户明确选择的演示点；模型不计算距离，不保证准入。无宠友提示放宽建议，修改硬约束必须用户明确同意。
- “扩大到5公里”保留其他确认条件，仅重查当前阶段；其他复杂修改重新提取并复核。地点缺坐标、无法验证的额外硬要求不得冒充满足。
- 工具错误与成功空结果分开；有限重试、取消和手动入口可用。草稿编辑确认后才执行原业务命令。
- 面板展示工具调用时间线：按实际顺序列出理解需求、模型请求和每次工具调用，含状态（进行中 / 完成 / 空结果 / 出错 / 已取消）、耗时与简短结果摘要；默认精简、可展开，手机不溢出；不伪造步骤、不展示模型推理，不持久化。
- 性格 / 活动的常见口语同义说法（随和、好相处、遛弯、溜达等）由程序同义词表映射为受控标签，仅作软排序并提示核实；无法映射的软词不阻断搜索，硬性措辞与距离、排斥、来源、准入未知、时间守卫不因此放宽。
- 不少于40条新增离线用例，常规测试不调用 Qwen；真实验证默认关闭，每轮次数及重试预算须获维护者明确批准。

### A 拍照建档验收条件

状态：已实现、Vitest 与 Playwright（mock）通过；真实视觉评测见 [AI_EVAL 第 7 步](AI_EVAL.md#第-7-步视觉评测拍照建档)；人工验收待确认。

- 用户在宠物档案表单中主动点击“识别照片”后，浏览器才把压缩缩略图（最长边 ≤512px、重新编码去除 EXIF / 位置信息）发给服务端视觉模型；原图不出浏览器，不自动识别。
- 模型只输出外观草稿（是否为狗、品种、体型、毛色、可见特征），不判断年龄、健康或性格；填入原表单（品种、体型，外观追加到见面前的小提醒）并标记“AI 填入”；主人编辑确认后才走原档案保存命令，不保存则持久化数据不变。
- 每个字段带置信度。高置信度字段可随“填入表单”自动填入；低置信度但有值的字段只显示“AI 猜测：xx（把握 nn%），请确认”和“采用”按钮，点了才填入该字段（同样带 AI 填入标记），不点不填；无值的字段留空提示手填。
- 品种与体型交叉校验：品种已达置信度门槛且在程序维护的常见品种体型表中时，模型体型在该品种允许范围内则保留；不在范围内则直接按表中该品种的典型体型自动填入（同样带 AI 填入标记），并提示如“体型按比格的典型体型（中型）填入，AI 原判断为小型”。有争议的品种在表中有典型体型和允许范围。品种低置信度或不在表中时不替换，按置信度规则处理。仍须主人点“确认保存档案”才写入。
- 非狗、看不清或多只狗时明确提示“无法识别 / 不确定”，一个字段都不填、也不提供“采用”；健康、年龄、性格类内容直接删除，不作为建议显示；不编造性格、健康或疫苗信息，不做诊断。
- 未配置密钥、超时、额度不足、Schema 校验失败均显示真实原因，表单仍可完整手填；不用样例结果替代。

### B 社区 AI 验收条件

状态：已实现、Vitest 与 Playwright（mock）通过；真实冒烟见 [AI_EVAL 第 8 步](AI_EVAL.md#第-8-步社区-ai-冒烟)；人工验收待确认。

- 帖子可带 0–5 个话题标签（每个 ≤12 字，只含中文、字母、数字、下划线），详情页展示，搜索可命中。
- 用户点击“AI 生成标题和标签”才调用：输入为已写正文，可勾选附带第一张照片的缩略图（与拍照建档相同的 ≤512px、去 EXIF 路径）。草稿为标题（≤20 字）、3–5 个标签和可选一句提示；不合格式、正文没有依据的健康 / 身份词被程序去掉，标题超长或可用标签不足 3 个则明确失败、不截断。填入表单并标记“AI 填入”，手改清除，可重新生成，不点发布不写入。
- 发布前预检只检查本次标题 / 正文 / 标签，分两层：程序规则（手机号、微信 / QQ 号、门牌级地址、外链与导流、明显违禁词）先查，再由模型做结构化判断（类别、原文片段、理由）。结果逐条显示类别、来源（程序规则 / AI 判断）并高亮片段。
- 规则命中的个人信息必须修改后才能发布（此时不调用模型）；其他建议可修改后重试或确认“仍要发布”；两层都未发现问题才直接发布。不静默拦截、不静默改写；任何修改都需重新预检（取舍见 [DECISIONS D025](DECISIONS.md)）。
- 模型未配置、超时、额度不足或输出不合格时显示“AI 预检未执行”及原因，程序规则仍生效，不显示“已通过”；用户可重试或确认“不经 AI 预检发布”。首版不对图片做审核；手动发帖流程不依赖 AI。

### 互助状态机与权限

`open → assigned → helper_done → completed`；`open / assigned → cancelled`。申请为独立实体：`pending → accepted / rejected / withdrawn`。

1. 求助者发布 open；其他可切换身份可申请，本人不可申请；同需求同申请者最多一个有效申请。
2. 求助者先复核并确认当前宠物 / 需求版本的照看清单（未知细节保留待确认），再接受一个 pending 申请，原子设置 assigned、acceptedApplicationId、helperId，其他 pending 变 rejected。申请者可在被接受前撤回。
3. 仅被选帮助者可将 assigned 标记 helper_done（清单来源失效须由主人重新确认）；仅求助者可确认 completed。不能一方直接完成，重复点击幂等。
4. 求助者可取消未开始的 open / assigned，必须说明是演示取消；open 取消同步拒绝 pending，assigned 取消保留已接受申请及取消记录。helper_done 后不能取消；首版不做纠纷 / 争议 / 重新分配。
5. 已过 startAt 的 open 禁止新申请 / 接受并显示已过期（派生状态）；assigned 允许事后记录完成。历史保留标题、双方、宠物和事件日志；修改已发布核心字段仅限 open 且无有效申请，否则取消重建。

### 活动规则

`scheduled → cancelled`；是否可报名由 scheduled、当前时间 < startAt、名额共同决定，开始 / 结束状态按时间派生。一个 owner + pet 组合最多一个有效报名，首版每身份每活动一只狗。组织者必须带自己宠物且占名额；容量 2–12。时间地点修改只限尚无人额外报名的未来活动，否则取消重建。取消报名释放名额，活动取消保留历史。

## 5. 演示主线与交付门槛

一段约 5–8 分钟的展示：切换到用户 A → AI 解析档案并确认 → 活动页智能约伴，确认日期 / 时间 / 5km 条件 → 优先查看已有活动 → 选择自己组局，查看宠友 / 地点 / 偏好差异 → 编辑活动草稿并确认创建 → AI 草拟临时互助 → 切用户 B 申请 → A 确认 → B 标完成 → A 确认完成 → 刷新查看记录。
