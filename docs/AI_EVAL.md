## 2. Phase 4 历史评测固定条件与判定

- 已实现 [runner](../evals/runner/evaluate.test.ts)、[命令入口](../evals/runner/run.mjs)、[核心与对抗用例](../evals/cases/core.ts)。报告位于 evals/reports/<runId>.json。核心35条，另有11条非法 / 忠实性对抗、8条单 / 多工具任务；默认mock共54条，live仅执行35+8，不把注入响应当真实模型效果。
- 固定评测时刻 `2026-10-17T02:00:00Z`（中国当天 10:00），时区 Asia/Shanghai；线上服务使用自身当前时间，只有本地评测入口可注入 clock，不允许生产客户端任意覆写 now。
- 核心抽取使用独立虚构fixture：help-intent提供pa豆包与pb团子；pet-profile / match-intent不附加其他档案事实，避免污染抽取。C06提供已知怕追逐，清单按给定习惯。工具任务使用createSeed冻结本地快照，当前本人宠物为年糕；实际ID由快照产生。
- 所有任务须符合 ARCHITECTURE 的统一响应与各任务 draft Schema。用例中的 null 表示不确定；clarifications 指向相关字段；文字允许等义表达，字段值 / 引用 / 日期用确定断言。
- 自动判定包括（不能代替人工语义审查）：原始 JSON 是否可解析；输出 Zod 是否通过；期望字段；禁止新增实体 / 错误单位 / 时间；草稿是否错误绕过澄清。建议文字另按人工 rubric 判定，不使用另一个 LLM 当唯一裁判。
- 每例状态 `not_run/pass/fail/error`。网络 / 额度失败记 error，不能从分母悄悄删除；not_run写明熔断/预算等原因，核心套件有not_run 就不能宣称完整通过。
- 报告计算Schema通过率、关键字段准确率、工具选择正确率、工具执行成功率、完整任务成功率。Schema分母为实际尝试的核心/工具用例（API error计失败），不含故意非法响应的V套件；Schema为模型原始实例/原生参数校验，不能用规范化后的成功替代。关键字段按明确断言逐项计数，ISO时间比较时间戳，原文摘录接受包含期望片段的完整原句；空数组仍须为空。工具选择按预期工具集合；执行成功按实际调用次数（含失败），完整任务需最终合约/引用通过及所有工具成功。not_run单列覆盖率，任何未执行项都不能宣称整套通过。对抗拦截率独立统计；没有使用另一个LLM裁判。
- 交付目标：35 条至少各执行 1 次；语义通过率 ≥95%（至少 34/35）、原始 Schema 成功率 ≥95%；进入 UI 的成功结果必须 100% 通过输出及语义防线；不存在实体 / 编造距离 / 未确认写入 / 危险照看建议为 0。任一关键风险失败必须修复或明确禁用对应能力，不能被总体分数抵消。
- 首轮后对 C03、C05、M03、M05、M07、H03、H04、H06、L03、L06 额外各跑 2 次（最少 55 次核心 live 调用），单列重复稳定性；预算允许再跑全套 3 次。不要把一次成功当作稳定保证。
- 先取得密钥与明确预算，预估最坏 token / 次数；runner 支持 `--dry-run` 只列用例与预算、`--case`、`--max-calls`、中断续跑，不自动重试无限调用。真实评测运行在获准本地 / 专用环境，也受预算保护，不能开放公网“评测绕过限流”接口。

## 5. 执行、报告与优化

可执行命令：

```powershell
npm run eval:ai -- --mode mock
npm run eval:ai -- --mode live --dry-run
npm run eval:ai -- --mode live --max-calls 80
npm run eval:ai -- --mode live --case TC04 --max-calls 8
npm run test:ai:live
```

runner只在本地启动，读取被忽略的.env.local。当前只允许用户指定的qwen3.8-flash，开启独立eval额度账本，普通服务账本不重置。真实传输次数含重试，--max-calls在fetch之前限制；单次输出上限1400 token，输入有界，日token保守预留300000。最少6.5秒间隔、429/503最多重试一次；连续3个上游失败会熔断，剩余not_run，不自动换模型。--case选择单例；--resume仅接受同模式、同套件、同模型、同Prompt/校验/用例版本并跳过已通过条目，不混合不同版本最佳结果。

JSON报告含runId、模式、固定模型、Prompt/用例版本、Git HEAD（本轮变更尚未提交时HEAD是Phase3；新报告另标gitDirty）、冻结时钟、实际调用数、usage、每例原始结构化输出/错误/时长/断言和五项指标。报告仅使用虚构fixture；不存密钥、reasoning_content或真实位置。调试的外层协议脱敏副本在被忽略的.local/ai-eval；工具结果的完整浏览器集成由独立live E2E验证。usage只包含提供方返回的已知用量，429/超时等未知消费不能视为零，也不据此宣称人民币成本。
