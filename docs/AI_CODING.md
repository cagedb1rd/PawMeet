# 用 AI Coding 开发 PawMeet

这个项目的代码、测试和文档主要由 AI 编码代理在人的指令和审查下完成。本文说明怎样组织这些工作，以及怎样用测试和评测兜住 AI 生成的代码。下文的例子都能在 Git 历史和项目文档中找到对应证据。

## 1. 规则和上下文写在仓库里

编码代理不记得上一次会话，所以项目把它需要的上下文都放进文件，每次会话先读：

| 文件 | 作用 |
| --- | --- |
| [AGENTS.md](../AGENTS.md) | 长期规则：范围与真实性（mock 不能冒充真实接口、没跑过的测试不能记为完成）、模型白名单与分模型 Token 预算、隐私（只发缩略图）、密钥与 Git 约定、文档分工 |
| [HANDOFF](HANDOFF.md) | 当前交接快照：目标与授权范围、已完成 / 未完成、阻碍、下一项可执行行动 |
| [PROGRESS](PROGRESS.md) | 进度事实，每一阶段分开标“已实现 / 已测试 / 已验收”；人工验收只能由人确认 |
| [PLAN](PLAN.md)、[DECISIONS](DECISIONS.md)、[AI_EVAL](AI_EVAL.md) | 任务依赖与每步的完成标准；关键取舍及原因；评测方法和真实证据 |

规则写进仓库，有两个作用。一是新会话不依赖聊天记录也能接着做。二是能约束代理的“讨好倾向”，例如 AGENTS 明确要求“不删测试、放宽断言或伪造结果掩盖错误”，评测要求“到额度即停，不靠重试刷绿”。

## 2. 一步一个会话，协调会话逐步核对

展示改进阶段的 13 步计划（[PLAN 第 7 节](PLAN.md#7-展示改进计划)）由一个协调会话推进：它按顺序为每一步开一个独立会话，各步不并行，共用同一个工作目录。每个会话只做被分配的那一步，完成后本地提交，并更新 PROGRESS 和 HANDOFF。协调会话读这些结果、核对差异，再开下一步。需要人做决定的事，例如追加模型预算、把对不上表的体型改为直接按表填入，都由用户在会话里确认，代理不替人决定。

每一步内部按同一个循环推进：

**读文档 → 拆成小任务 → 看差异 → 跑相关测试 → 写证据 → 提交**

- 先写验收条件，再实现最小完整流程。例如拍照建档和社区 AI，先在 [PRD](PRD.md#a-拍照建档验收条件) 中写好验收条件，再动手实现。
- 代码步骤结束时跑 lint、typecheck、Vitest、build，关键流程跑 Playwright；纯文档步骤只检查链接、范围和敏感信息，不假装跑了业务测试。
- 提交前审查暂存差异，确认没有密钥、私有图片或本地账本。

## 3. 用测试和评测兜住 AI 生成的代码

AI 写的代码看起来合理，不等于真的对。以下是开发中由评测或测试发现、修复后再用回归测试锁住的真实例子：

| 问题 | 怎么发现的 | 修复与证据 |
| --- | --- | --- |
| 模型根本没调用工具，却回答“已查询…”“没有符合条件的结果”，而生产代码照单全收 | 多模型真实评测：qwen3.8-27b 在 6 个工具用例里都没返回 `tool_calls`（[报告](../evals/reports/2026-10-18T15-43-35-749Z-qwen3.8-27b-live.md)） | 没有工具结果的一轮只接受两种澄清回答，否则判为非法输出；新增 10 项回归测试，撤掉修复后其中 8 项失败（[`48fe8da`](https://github.com/cagedb1rd/PawMeet/commit/48fe8da)） |
| 接入 Gemini 后工具调用直接报“上游响应非法” | 正式评测前的小额冒烟（[修复前](../evals/reports/2026-10-18T16-45-41-815Z-gemini-3.8-flash-live.md) / [修复后](../evals/reports/2026-10-18T16-46-33-380Z-gemini-3.8-flash-live.md)） | Gemini 的流式 tool_calls 不带 `index`，解析器却把它当必填字段；改为缺 `index` 时按 id 归并，并用 mock 单测覆盖（[`5420f83`](https://github.com/cagedb1rd/PawMeet/commit/5420f83)） |
| “回答修复”那一轮在 Gemini 上返回 HTTP 400 | 跨厂商评测中 gemini-3.5-flash-lite 的一次失败 | 修复指令用了 system 角色，Gemini 把它移出对话后，请求变成以模型回合结尾；改为 user 角色并加单测（[`34ede12`](https://github.com/cagedb1rd/PawMeet/commit/34ede12)） |
| 工具报错后，模型反复调用同一工具，直到撞上 4 轮上限 | 跨厂商评测：两个 Gemini 的 CT06 / CT07（[对比表](../evals/reports/2026-10-18T17-16-17-753Z-compare-live.md)） | 任一工具出错，下一轮就不再提供工具，强制如实收尾；撤掉修复后 9 项回归测试失败（[`278a79d`](https://github.com/cagedb1rd/PawMeet/commit/278a79d)）。尚未用真实调用复测 |
| 用户说“不要大型犬”，模型却输出“只要小型和中型” | 首次约伴真实调用：JSON 和 Zod 都合法，被事实守卫拒绝（[报告](../evals/reports/2026-10-16T21-57-40-954Z-live.json)） | 守卫保持不放宽，Prompt 改为只记录明确的包含 / 排斥值，禁止把排斥展开为正向补集，并新增离线回归（[`59534df`](https://github.com/cagedb1rd/PawMeet/commit/59534df)） |
| 弹窗关闭后，键盘焦点没有回到触发按钮 | 新增的 Playwright 键盘用例首轮失败（全套 86/94，其中 2 项是这个问题） | 改为在布局阶段关闭弹窗并恢复触发元素的焦点，此后全套 94/94（[`381bf24`](https://github.com/cagedb1rd/PawMeet/commit/381bf24)） |
| 视觉模型对体型“自信地错了”：品种认对（0.95），体型错一档（0.85） | 16 张带标签图片的真实视觉评测 | 加入程序维护的品种体型表做交叉校验，再用已保存的原始输出离线复算：lite 自动填入的错误从 1 个降到 0 个（[`3f5c284`](https://github.com/cagedb1rd/PawMeet/commit/3f5c284)、[`0122de1`](https://github.com/cagedb1rd/PawMeet/commit/0122de1)，[复算报告](../evals/reports/2026-10-18T19-55-06-421Z-vision-recheck-offline.md)） |

共同的做法：

- **先复现，再修复**：每个修复都带回归测试，并验证撤掉修复后测试确实会失败，确认测试真的能抓住这个问题。
- **守卫不为通过而放宽**：模型输错时改 Prompt 或改流程，不清洗模型输出、不放宽校验。只有确认是测试期望写错（例如用例里工具名的顺序）才改测试，并写明原因。
- **离线优先**：修复先用 mock 和已保存的真实原始输出验证，不为验证一个修复去额外消耗模型额度。真实效果没复测的，就写“未验证”。

## 4. 如实记录失败，不刷绿

- 评测按模型设硬性 Token 上限，在请求发出前预留额度，到额就停（[D023](DECISIONS.md)）；不自动换模型，也不靠重试刷出通过。
- 网络失败和模型答错分开统计。从海外连接百炼北京端点经常超时，评测报告如实写明 Qwen 没有跑完，不把网络问题写成模型能力差，也不拿 Gemini 的结果顶替。
- 模拟数据的报告文件名带 `-simulated`，汇总代码拒绝把它和真实数据合并（[D021](DECISIONS.md)）。
- 未达标的结果保留在文档里，例如早期核心用例 31/35 没达到门槛、真实高德联调有 2 项失败（[PROGRESS](PROGRESS.md)）。被完整重跑取代的旧运行也留档，并注明已被取代。
- 测试首轮失败的次数会写进 PROGRESS，不把重跑后的通过当作首轮通过。

## 5. 局限

- AI 生成的规则（如发布预检的正则和词表）只覆盖写到的情况，漏报和误报样例记录在 [AI_EVAL](AI_EVAL.md#第-8-步社区-ai-冒烟) 和单测中。
- 测试兜得住“已知会出错的地方”，兜不住没想到的场景；真实页面（live UI）、真机和国内网络下的表现仍待验证，见 [PROGRESS 未验证项](PROGRESS.md#未验证项)。
